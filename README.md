## AI 帮你选产品，通常错在这四件事

| 症状 | 它实际做了什么 |
|---|---|
| 「给你三个选项」 | 候选池来自训练数据里出现频率最高的爆款，**不是最适合你的**。真正合适的那款可能根本不在里面 |
| 「综合考虑音质、降噪、续航」 | 权重是它悄悄替你定的。**综合是什么意思？谁占多少？** 你既不知道，也无法反对 |
| 「这款性价比高」 | 价格被折进了分数。这等于它替你做了「省 500 块 = 少 20 克重量」这个兑换——**而这个兑换率只有你自己知道** |
| 「推荐 A 款」 | 从不告诉你这个排名有多脆弱。换个候选池、改个权重、数据偏 5%，结论会不会全变？**不知道** |

这四条不是「AI 不够聪明」，是**流程缺了四道关卡**。Product Pick 就是这四道关卡。

## 它做了什么不同的事

### 一、候选池：从榜单反推品牌，再从品牌展开产品线

大部分人（和大部分 AI）挑产品的方式是抄榜单。这有个隐蔽的损失：

> **榜单只有 10 个位置。** 一个品牌有 12 款睡袋，上榜 1 款、落榜 11 款——**那 11 款是被「榜单容量」淘汰的，不是被「性能」淘汰的**。而你要的那款，很可能正好是第 4 款：温标一样、便宜 30%。

所以流程是 **榜单找品牌 → 品牌展开产品线 → 产品线里选型号**：

```
b1  查 1–3 个该类目权威榜单（限近两年），只记品牌名，不记产品名次
b2  逐品牌进官网看完整产品线（不是只看看上榜那款）
b3  在产品线里挑符合硬门槛的型号，补国内可购性
```

b1 阶段有条纪律：**只取品牌，不取产品的榜单评分。** 因为榜单的名次是别人权重下的结果——把它摆到你面前，你对属性的排序就被污染了。

榜单的权威性用五条判据卡（披露方法 / 独立于厂商 / 两年内更新 / 品类专项 / **敢说「不推荐」**）。最快的过滤器是最后一条：**翻到文末，看有没有劝退段落。只夸不贬的榜单，本质是广告位。**

### 二、属性后验，权重现拍，而且必须过闸门

**属性是搜出来的，不是预设的。** 睡袋看温标蓬松度，耳机看降噪深度，没有通用属性表。

**权重由你排序，算法换算（ROC）。** 人不擅长报百分比——让他填「重量 30%、蓬松度 25%」，他会填出一组接近等分的值，因为等分看起来客观。但人非常擅长排序。所以只问排序，基数权重交给 [ROC](skills/product-pick/references/weighting.md)。

**计算完不直接往下走，先过闸门：**

```
按你的排序换算出来是：
  总重        45.7%   ← 差不多一半的话语权
  舒适温标    25.7%   ← 四分之一
  蓬松度      15.7%
  压缩体积     9.0%
  面料         4.0%   ← 基本不影响排名

这组权重你认吗？
```

闸门包含三项体检，其中第三项最容易漏、也最伤：

> **有没有门槛混进了加权项？** 一旦「会不会受伤」被压成 3% 的扣分，矩阵就会输出「温标不够但便宜 300，划算」这种结论。**数字上没错，逻辑上杀人。**

时序锁：权重必须在**看到任何属性取值之前**拍完。只看到型号名和价格区间不算「看到数据」——这个界定让「先全面了解」和「权重不被结果污染」能同时成立。

### 三、价格只展示，不折成分数

把价格算进综合得分，等于替你做了权衡。所以得分只算产品力，价格单列成轴，判断权留给你：

```
| 产品 | 价格 | 得分 |
| 天石极光LIGHT700 | ¥2,000 | 72.81 |   ← 唯一的价格前沿解
| 黑冰Z700        | ¥2,479 | 72.81 |   多花 ¥479 买 0 分
```

> 这条不只是偏好。Hämäläinen 等人的 even swap 实验显示：一旦钱成为所有权衡的通用量尺，受试者会系统性偏向低成本方案——走「价格路径」的人 **80%** 选了低价项，其他路径只有 **53–63%**。价格一旦参与计算，判断就被扭曲。

### 四、结论必须带稳健性检验和失败绊网

每个结论都附三样东西：

- **权重敏感性解析解**：要改多少权重才能换掉赢家？如果答案是「总重权重砍掉 75%」，那是稳健。如果是「动 2% 就翻盘」，它会直接告诉你**这两款实质等价，别纠结**。
- **数据误差检验**：按每个产品数据来源的可靠度（A 官方 / B 实测 / C 电商页 / D 社区）给 σ，全部往不利方向偏移后重算。结论翻转意味着「原结论建立在乐观数据上 → 去核数据，别改结论」。
- **失败绊网**：提前定义「什么时候该承认选错」。没有这一条，沉没成本会一直追加——已经花 3000，就再买个内胆吧，再换个好睡垫吧，每一笔单看都合理，合起来是当初没想清楚。

## 一次真实运行

以下是这个 skill 实际跑完的一次「买睡袋」决策（完整存档见 [`examples/sleeping-bag.md`](examples/sleeping-bag.md)）。

用户门槛：舒适温标 ≤ -8℃、羽绒、适配 181cm、面料不能两年就废。
权重（用户排序 + ROC）：总重 40.8 / 舒适温标 24.2 / 绒质 15.8 / 蓬松度 10.3 / 面料 6.1 / 压缩体积 2.8。

**完整评分表**（每项贡献 = 归一化值 × 权重 × 100，横向相加 = 总分）：

| 产品 | 总重 | 舒适温标 | 绒质指数 | 蓬松度 | 面料 | 压缩体积 | **合计** | 价格 |
|---|---|---|---|---|---|---|---|---|
| 黑冰 Z700 | 40.80 | 8.07 | 15.80 | 0.00 | 6.10 | 2.80 | **73.57** | ¥2,479 |
| 天石极光 LIGHT 700 | 40.80 | 8.07 | 15.80 | 0.00 | 6.10 | 1.96 | **72.73** | ¥2,000 |
| Parsec 0 | 23.20 | 16.13 | 9.03 | 10.30 | 0.00 | 1.76 | **60.42** | ¥4,320 |
| Phantom 0 | 13.28 | 24.20 | 4.51 | 5.15 | 3.05 | 0.59 | **50.78** | ¥5,000 |
| Cumulus Spotter 600 | 40.80 | 0.00 | 0.00 | 5.15 | 0.00 | 1.96 | **47.91** | ¥4,360 |
| Montbell SDH800 #0 | 34.88 | 0.00 | 0.00 | 0.00 | 6.10 | 1.92 | **42.90** | ¥3,400 |
| WM Kodiak MF | 0.00 | 20.97 | 0.00 | 5.15 | 0.00 | 0.00 | **26.12** | ¥6,620 |
| **该项满分** | 40.80 | 24.20 | 15.80 | 10.30 | 6.10 | 2.80 | **100.00** |

这张表一眼能读出几件事，**而排名表读不出来**：

- 前两名逐行相减，差距只在「压缩体积」这一项（2.80 vs 1.96 = 0.84 分）→ 实质等价，该用价格和风险决定，不该强行排名
- 「蓬松度 0.00」不是笔误，是 800FP 正好是全池最低，10.3% 权重一分未得
- 最贵的 WM Kodiak（¥6,620）得分垫底——**在这个池子里，价格和得分是负相关的**

**最终结论**：推荐天石极光 LIGHT 700，理由是「它和黑冰 Z700 在所有能核实的属性上一模一样，但便宜 ¥479，而且这套规格里黑冰的假货是系统性问题」——而不是「综合性能更优」这种话。

同时给了两条绊网：

> 连续两次在 -5℃ 以下被冻醒 → 厂标判断错了，**加内胆（¥400），别换袋（¥4,000）**。换袋是沉没成本在驱动。

> 背部发凉优先查睡垫 R 值。睡袋的羽绒在你身下被压扁，几乎不隔热——**背部保暖几乎全靠睡垫。**

## 工作流（13 步）

| # | 步骤 | 关键动作 |
|---|---|---|
| 0 | 开题 | 确认品类。**不问预算** |
| 0.5 | 问题重构 | 三问：选项消失测试 / 归因检查 / 问题规模。**若「买错了东西」，直接中止选型** |
| 1 | 需求引导 | 一次一问，5 问骨架。核心是「什么会让你后悔」而不是「你最看重什么」 |
| 1.5a | 属性发现 | 这个品类该看什么参数、什么是虚标重灾区、买家最常踩什么坑 |
| 2 | 属性设计 | 分三层：硬门槛（一票否决）/ 可量化项（加权）/ 主观项（结论阶段否决权） |
| 2.5 | **拍权重** | 用户排序 → ROC 换算 → **核对闸门**（三项体检 + 显式确认）→ 落锁 |
| 1.5b | 候选发现 | **榜单找品牌 → 品牌展开产品线 → 产品线选型号**；中英双轨，国别覆盖硬要求 |
| 3 | 候选池 | 先给品牌全景表，再给长名单；用户圈定，上限 8 个 |
| 3.5 | 锁定检查 | 「这个选择会封死你未来两年的什么选择？」生态/功能/退路三类锁定 |
| 4 | 数值采集 | 逐产品逐属性，每值带来源等级（A/B/C/D）与日期。**取不到就写「未知」，绝不估算** |
| 5 | 打分 | 脚本算，不许口算——因为敏感性分析需要精确解析解 |
| 6 | 双前沿 | 价格前沿（多花 X 买到什么）+ 物理轴前沿（多减 100g 划不划算） |
| 7 | 结论 | 结论先行 + **完整评分表** + 盲区三类 + 组合方案 + 失败绊网 + 存档 |
| 8 | 预算重算 | 「预算 2000 以内重新评估」→ 加参数重跑，**不覆盖原结果**，两份并存 |

### 信息盲区固定三类

每份结论都必须给，空着也要写「无」并说明核验依据：

| 类别 | 写法 |
|---|---|
| **查不到** | 属性/型号 + 缺失原因（官方未公布 / 仅海外版 / 评测未覆盖） |
| **有争议** | 冲突双方数据并列 + 我的倾向判断 |
| **已排除** | 型号 + 排除理由（门槛不过 / 国内无售 / 抽检不合格 / 停产） |

这一节不是免责声明，是告诉你**这次决策建在多少不确定之上**。

## 方法论出处

不是拍脑袋设计的流程，每一步都有出处：

| 环节 | 方法 | 出处 |
|---|---|---|
| 权重换算 | ROC（rank-order centroid） | Barron & Barrett, 1996, *Decision Quality Using Ranked Attribute Weights* |
| 归一化 + 加权和 | MCDA / MAUT | Keeney & Raiffa, *Decisions with Multiple Objectives* |
| 非支配解筛选 | Pareto 前沿 | —— |
| 流程骨架 | PrOACT 八要素 | Hammond, Keeney & Raiffa,《决策的艺术》(*Smart Choices*) |
| 失败绊网 | Prepare to be Wrong / tripwires | Heath 兄弟,《决断力》(*Decisive*) |
| 敏感性解析解 | 加权和下换赢家的最小权重变动闭式解 | 本项目推导，见 [`references/scoring-and-frontier.md`](skills/product-pick/references/scoring-and-frontier.md) |

**刻意没用的方法**：even swap（等价置换法）虽出自同一学派，但实证有路径依赖与量尺效应缺陷（Hämäläinen 等 2015），会系统性压低高价项；决策树要给每个后果估概率，对买睡袋太重，而且人估的概率通常不比「这份数据可不可靠」更准。

## 它不适用的时候

这一节比上面所有内容都重要，因为它决定你会不会白花时间。

| 场景 | 为什么不行 | 该用什么 |
|---|---|---|
| **要不要买**（「我该不该买个跑步机」） | 这是需求真伪问题，不是选型问题 | 用 `life-decision` |
| **买完想找背书** | 你已经有答案了，这不是决策，是求安心 | 直接问「这款有什么已知问题」 |
| **只有一个候选** | 打分需要至少 2 个候选才有意义；1 个候选归一化后必然 50 分，纯占位 | 直接查参数或看长测 |
| **医疗 / 法律 / 投资** | 后果不可逆且需要执业资质，不在能力边界内 | 找专业人士 |
| **安全类产品且认证不全** | 头盔、绳索、儿童座椅、燃气设备——认证不过直接出局，**不给权衡空间** | 流程会强制中断，不产出推荐 |
| **时间极度敏感**（今晚就要用） | 充分搜索要 20–40 分钟 | 直接看专业媒体榜单，接受次优 |

还有一条边界值得明说：**这个 skill 依赖搜索到的数据质量。** 如果某个品类全网都只有厂商软文（没有独立实测、没有二手残值、没有抽检记录），它会诚实地告诉你「这次决策建在很薄的信息上」，而不是假装算得很准。

### 快速试一下打分引擎

不需要装 skill，直接跑：

```bash
python3 skills/product-pick/scripts/pick.py roc --order "总重,舒适温标,蓬松度,压缩体积,面料"

python3 skills/product-pick/scripts/pick.py run \
  --attrs "蓬松度:+,总重:-,压缩体积:-,面料:+" \
  --weights "46.7,25.7,15.7,9.0,4.0" \
  --data "A款:750,780,8.2,4;B款:800,1050,9.5,3;C款:650,620,6.8,2" \

```

### 跑测试

```bash
python3 -m unittest discover -s tests -v
```

22 个测试，锁住打分引擎里几个容易静默坏掉的性质：ROC 权重和为 1 且单调递减、归一化端点方向正确、**得分构成横向相加等于总分**、无区分度属性中性化为 0.5、`flip_factor` 确实能把分差归零、价格不参与得分、门槛与缺值候选不进排名。

其中有一个是**回归测试**：两个产品除一项外完全相同，全部差距必须落在那单独一项的贡献里。这正是睡袋那次踩到的坑——压缩体积口径不一致，凭空造出 2.76 分的差距。CI 在 Python 3.8 / 3.10 / 3.12 / 3.13 上跑。
