# 需求引导 · Elicitation

Step 0.5（问题重构）与 Step 1（需求引导）的细则。

目标不是「收集信息」，是**在搜索开始前把问题和评价维度都锁定**——问错了，后面搜再多也是朝错误方向使劲。

---

## 〇、问题重构（Step 0.5）

PrOACT 的第一要素是 Problem，不是 Alternatives。书里那句话说得直接：多数人「试图为错误的问题找到正确的解法」。

这一节要挡住的，是**需求本身就不成立**的情况。

### 问 1 · 选项消失测试

```
如果这个品类的所有产品明天全部停产、再也买不到，你会怎么办？
```

不要给选项，让他自由回答。四种典型回答对应四种完全不同的处理：

| 回答 | 说明 | 处理 |
|---|---|---|
| 「那就算了，不买了」 | 需求不成立，只是被货架激发的购买欲 | 停止选型，转 `life-decision` 做需求审计 |
| 「借一个 / 租一个」 | 使用频率低，拥有不是最优解 | 把「租赁」作为正式候选进池，和购买一起比 |
| 「我把现有的修一下 / 凑合用」 | 现有装备还能用，缺的是配件不是整件 | 转向「修/配件」问题，重新定义品类 |
| 「换个办法解决」（比如冷了多穿、糊了练技术） | 问题框架错了，产品是错误解法 | 回 Step 1 重问场景，或直接说「你要的不是这个东西」 |

工作坊实验里，约八成人在三分钟内通过这个问题想出了比原方案更好的解法。所以它不是形式主义——它是成本最低的翻盘机会。

**追问（拿到「换个办法」时）**：
> 「如果只能用一个不是专门为此设计的东西解决，你会用什么？」

这个问题常常直接给出组合方案的雏形。

### 问 2 · 归因检查

```
你说的「不够用」，最可能是产品的问题，还是搭配或用法的问题？
```

用户几乎永远归因于产品，因为他在看产品。四类高频误判：

| 抱怨 | 用户以为 | 实际常常是 | 验证动作 |
|---|---|---|---|
| 睡袋太冷 | 温标不够 | 睡垫 R 值太低（热量从地面流失远大于空气）、穿太多出汗后失温、帐篷漏风 | 问 R 值；问是否穿羽绒睡 |
| 照片不清晰 | 机身不行 | 镜头素质、光线、手持抖动、对焦模式设错 | 问镜头型号；看样张 EXIF |
| 跑鞋不够软 | 缓震不足 | 跑量突增、跑姿、鞋已过寿命（中底衰减） | 问月跑量和这双鞋的里程 |
| 降噪没效果 | 耳机不行 | 佩戴密封不良（换耳塞套解决）、风噪场景 | 问是否试过其他尺寸耳塞套 |
| 帐篷漏雨 | 防水不行 | 搭设位置积水、地布缺失、缝线未做密封 | 问营地选择和搭法 |

**追问模板**：「你试过 ___ 吗？」——填一个不花钱的验证动作。如果他说没试过，那"买新的"这个动作就缺少依据。

### 问 3 · 问题规模

```
这件事的代价是买错亏钱，还是买错会受伤？
```

三档：

| 档位 | 例 | 流程影响 |
|---|---|---|
| 亏钱但可逆 | 大部分消费品 | 正常流程，允许权衡 |
| 亏钱且不可逆 | 定制、海淘、清仓 | 加强对「退路锁定」的检查（Step 3.5） |
| 会受伤 | 头盔、绳索、安全带、儿童座椅、燃气设备 | **认证不全一票否决**，不给权衡空间 |

### 判定规则

**三问里有两问指向「问题不在产品」，就停止选型流程。**

说清三件事，不要含糊：
1. 真正的问题是什么（一句话）
2. 为什么继续选型是浪费（具体到他的场景）
3. 下一步该做什么（换问题 / 租 / 修 / 组合方案 / 转 life-decision）

不要为了走完流程而假装问题成立。这是本技能最容易犯的错，因为承认「买错东西了」会让前面所有准备工作作废——但那比让他花 3000 块解决一个不存在的问题好得多。

## 一、问法硬约束

1. **一次一问**，每问 3–4 个可点选选项
2. 选项**互斥**，覆盖真实分布，不要「都可以」这种逃逸项
3. 每问带推荐项 + 一句理由，但推荐要能被推翻
4. 选项要**具体到能改变结论**的程度。问「使用频率」不要给「经常/偶尔」，要给「每月 1 次以上 / 每季度 1–2 次 / 一年几次」——因为前者无法换算成使用成本，后者可以

## 二、5 个通用问

### 问 1 · 用途与场景

不要问「你要买什么价位的」，先问场景。四个选项覆盖典型分布：

```
你用它的场景最接近哪一种？
A. 高频刚性（每周至少一次，缺了影响正常生活/工作）
B. 阶段性集中（每年 2–3 次高强度使用，其余时间收纳）
C. 低频备用（一年几次，属于"有备无患"）
D. 日常轻度（几乎每天用，但强度很低）
```

**追问（A/B 必问）**：具体环境参数。睡袋要问夜间最低温、营地海拔、湿度；跑鞋要问路面、里程、配速；耳机要问通勤方式、单次佩戴时长。

这一步拿到的数字直接变成硬门槛。

### 问 2 · 硬性外部条件

```
有没有"不合这个就绝对不行"的条件？（多选或口述）
```

引导用户说出的方向：

- **尺寸/容量**：身长、脚长、肩宽、容积
- **兼容性**：是否必须与现有装备配合（睡袋要配现有睡垫的 R 值、相机要配已有卡口、镜头要配已有滤镜口径）
- **法规/合规**：安全认证、航空携带限制、场地规定
- **物理限制**：承重上限、收纳尺寸（宿舍柜子塞不进去就是不能用）

**这一问的产出是硬门槛清单，不是偏好。** 用户常把偏好混进门槛（「我想要轻的」不是门槛，「我负重不能超过 8kg」才是）。要区分：门槛是加个「必须」还成立的东西。

### 问 3 · 自身条件

```
有什么身体条件会决定"合不合用"？
```

- 身高体重（决定尺码和承重）
- 体型特征（肩宽、脚型宽窄、头围）
- 生理特点（怕冷/怕热、易出汗、过敏）
- 经验水平（新手更容易高估装备作用、低估技能）

**怕冷这一项对睡袋尤其关键**：同一条 EN 舒适温标，怕冷的人要往上加 3–5℃ 才够用。这不是矫情，是可量化的个体差异。

### 问 4 · 现有装备与替换原因

```
为什么现在想换？最接近哪一种？
A. 现有装备明确不够用（具体哪里不够：____）
B. 现有装备还能用，但想升级体验
C. 第一次买这个品类，没有对比基础
D. 现有装备丢了/坏了，需要补上
```

**为什么必问**：这是免费的基准率信息。

- 选 A：知道了现有装备的具体短板 → 新品的核心属性直接确定
- 选 B：警惕「想买」伪装成「需要」，追问具体哪里不满意
- 选 C：新手，需要额外解释品类常识，且要提醒高估装备作用的风险
- 选 D：同款是否已停产、是否有已知缺陷

C 选项要特别处理：**新手最容易在参数上过度投入**。睡袋的例子是拼命追蓬松度，但实际瓶颈是睡垫 R 值。

### 问 5 · 什么会让你后悔（核心问）

**不要问「你最看重什么」**。这个问题会得到政治正确的答案：性价比、品质、耐用。这些答案无法转成权重——所有产品都声称自己有。

问这个：

```
假设买回来用了三个月，发现选错了。下面哪种"错法"你最不能接受？
A. 性能不够用（在最需要的那次，它掉了链子）
B. 花多了（同类产品花更少钱也能满足）
C. 不够省心（用起来麻烦，所以用得少，最后吃灰）
D. 不够好看/不够满意（功能没问题，但每次看到都不太舒服）
```

四种后悔对应四种权重倾向：

| 选择 | 倾向 | 通常对应权重 |
|---|---|---|
| A | 性能优先 | 核心性能属性排第一，价格可以往后 |
| B | 价格敏感 | 价格敏感度高，但要小心「便宜但不够用」的二次后悔 |
| C | 使用摩擦优先 | 重量、收纳、维护成本权重上升 |
| D | 主观项权重高 | 颜值/手感不能只做否决项，要考虑提权 |

**可以多选，但要求排序**。多选后追问一句：「如果只能保一个，保哪个？」——这一问比四个选项本身更有信息量，因为它逼出真实的序数。

## 三、品类补问清单

5 问答完后，按品类补 1–3 个。补问来源是 1.5a 搜到的「买家最常踩的坑」——不是凭空想。

| 品类 | 必补问 |
|---|---|
| 睡袋 | 睡垫 R 值是多少（决定温标是否够用）／拉链左右侧偏好（决定能否与另一条拼合）／是否需要能塞进现有压缩袋 |
| 跑鞋 | 足弓与足型（宽楦/窄楦）／是否有旧伤（决定缓震需求）／跑量在增加还是维持（决定是否该买次顶级） |
| 耳机 | 是否需要同时连两台设备／戴眼镜（决定夹头）／是否在意外界声音（决定开放还是封闭） |
| 相机/镜头 | 已有卡口与机身／主要题材（风光要广角、纪实要轻便）／是否接受手动对焦 |
| 笔记本 | 是否移动办公（决定重量与续航优先级）／是否有特定软件需求（决定平台） |
| 床垫 | 睡姿（决定软硬）／体重分布（决定支撑）／是否分床（决定是否要抗干扰） |
| 户外硬装备 | **是否有认证、认证标准编号**（安全类，认证不全直接出局） |

## 四、回答质量判定

| 用户说的 | 判定 | 处理 |
|---|---|---|
| 「差不多就行」「看性价比」 | 无效 | 追问具体场景，或让他在后悔四选一里挑 |
| 「越轻越好」「越大越好」 | 单维化，无效 | 追问「如果轻 100g 要多花 800，还轻吗」 |
| 「预算 2000 左右」 | 有效但是软约束 | 记为参考，不做过滤条件；如果用户坚持，走 Step 8 单独一节 |
| 「我朋友说 XX 好」 | 二手信息 | 记为新候选，不作为结论依据 |
| 「我就是喜欢那个样子」 | 有效的真实偏好 | 承认它，进主观项，不试图说服 |

## 五、反模式

**不要**在需求阶段就让用户看产品。一旦看到型号，后面的所有回答都会被锚定——用户会开始描述「为什么那款适合我」，而不是「我需要什么」。

**不要**把 5 个问题合并成一段长文一次问完。用户会凭感觉挑几个答，剩下的默认跳过。

**不要**在用户给出模糊回答时自行补全。「大概三季吧」不能推出「舒适温标 0℃」——要问清夜间最低温。

**不要**在需求摘要里加入用户没说的东西。复述要逐条对应他的原话，这既是确认，也是在教他「你的需求已经被准确记录了」。
