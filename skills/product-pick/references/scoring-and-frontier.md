# 打分与前沿 · Scoring & Frontier

Step 5–6 的细则。这里写的都是公式，但重点在每节末尾的**失效边界**——方法什么时候会骗人，比方法本身更重要。

---

## 一、归一化

不同属性单位不同，不能直接相加。先把每个属性映射到 [0,1]。

**正向属性**（越大越好，标 `+`）：

```
n_ij = (x_ij − min_i) / (max_i − min_i)
```

**负向属性**（越小越好，标 `-`）：

```
n_ij = (max_i − x_ij) / (max_i − min_i)
```

**所有产品同值**：分母为 0，该属性全体记 0.5，标注「本批次无区分度」，不参与排名差异。不要删掉它——它说明用户认为重要但市场没有差异，这是信息。

### 为什么用 min-max 而不是 z-score

- z-score 假设分布近似正态，候选只有 5–8 个时不成立
- z-score 的结果不落在固定区间，加权后不好解释
- min-max 的结果是「在这批候选里的相对位置」，正好对应「我该在这几个里选哪个」这个实际问题

### 失效边界（重要）

**1. 小样本放大效应**

只有 3 个候选时，最差的必然是 0，最好的必然是 1，**无论真实差距多小**。

```
重量：780 / 800 / 820
归一化后：1.0 / 0.5 / 0.0
```

真实只差 40g（5%），归一化后看起来差了一个满格。这会让「轻 20g」被当成重大优势。

**处理**：结论里给原始值，不要只给归一化分；当 max/min 比 < 1.2 时（差距很小），在表里标注「本维度差异有限」。

**2. 异常值压缩**

一个候选特别差（重量 2500g），会把其他全部压到 0.8–1.0 区间，之间的差异被挤成小数点后两位，权重再准也分不出高低。

**处理**：脚本会检测 max/min > 3 的情况并警告；此时考虑用中位数截断（把超过 2 倍中位数的值截到 2 倍），或干脆把极端款排除出候选池。

**3. 归一化后的分数不是绝对好坏**

60 分不意味着「及格」，只意味着「在这批候选里的中间位置」。换个候选池，同一款产品的分数会变。

**所以永远不要跨品类、跨批次比较得分。**

## 二、加权求和

```
S_j = 100 · Σ_i w_i · n_ij
```

- `w_i` 来自 ROC 换算（见 `weighting.md`），和为 1
- 价格**不参与**（`w` 里没有价格项）
- 得分范围 0–100，但如前所述，它的含义是「本批次内的相对位置」

## 三、敏感性分析

矩阵唯一真正值钱的部分。它回答：**这个结论有多脆弱。**

### 公式

设 W 为当前赢家，R 为挑战者，`d_i = n_Wi − n_Ri`（两者在属性 i 上的归一化差）。

两者得分差：`Δ = Σ_i w_i · d_i`，W 赢当且仅当 `Δ > 0`。

现在问：把属性 k 的权重乘以 f（其余不变，整体重新归一化），Δ 何时变为 0？

重新归一化后 Δ 的符号等价于分子 `f·w_k·d_k + Σ_{i≠k} w_i·d_i` 的符号。令其为 0：

```
f = − Σ_{i≠k} w_i·d_i / (w_k·d_k)
```

- `f = 1` 表示当前权重
- `f = 0.8` 表示「属性 k 的权重只要降到原来的 80%，赢家就换人」
- `d_k = 0` 时 f 无解（该属性上两者无差异，撬不动结论）

对所有 (k, R) 组合求解，取 `|f − 1|` 最小的那一个，就是**最脆弱的翻转点**。

### 判读

| \|f−1\| | 判定 | 输出 |
|---|---|---|
| < 0.15 | 极不稳健 | 「这两款实质等价。差异小于打分噪音，别用矩阵决定，用次级标准（更便宜/可退/有货/交期快）」 |
| 0.15–0.30 | 不稳健 | 「结论依赖权重设定。如果你对 X 的看重程度和排序不一致，赢家会变」 |
| > 0.30 | 稳健 | 「最敏感的一条也要把 X 的权重改动 30% 以上才会翻盘」 |

**阈值 0.15 和 0.30 是可调的**，但它们的存在比数值重要：没有这条判据，矩阵会给出一份看起来很确定的排名，而真实情况可能是「随便选」。

### 失效边界

- 只对**赢家 vs 挑战者**做敏感性，不对全部两两做。三款互有胜负时，说明它们确实各有取舍，这时候前沿图比敏感性更有用。
- 敏感性只管权重，不管**数据误差**。如果一个值本身可能有 10% 误差（比如实测重量口径不一），那敏感性结论在这之上还要再打折扣。

## 四、数据误差检验（最坏情况）

### 为什么需要

打分假设每个数字都是准的。但真实情况是：温标是厂商标称（虚高 3–5℃ 很常见）、重量是不含配件的官标、价格是活动价。

这些误差**不是随机的**，方向高度一致——厂商倾向于公布对自己有利的值。所以只做权重敏感性不够：它回答「如果我的偏好不同」，不回答「如果数据本身是错的」。

### 做法

1. 给每个产品一个**相对**不确定度 σ（按来源等级定，见 `sourcing.md`）
2. 对**越大越好**的属性：`x - |x|σ`
3. 对**越小越好**的属性：`x + |x|σ`

这里使用绝对值是为了正确处理温标等负数指标。例如舒适温标 `-9℃` 是“越小越好”，10% 的不确定度应向不利方向移动到 `-8.1℃`，而不是 `-9.9℃`。
4. 重新归一化、重算得分、重排名
5. 与原名次对比

```bash
python3 scripts/pick.py run ... --worst "A款:0,B款:0.12,C款:0.05"
```

### 为什么必须按产品给，不能统一偏移

统一偏移对 min-max 归一化是**无效的**：所有产品乘同一个系数，相对位置完全不变，排名一点不动。

所以 σ 表达的是「这款的数据比那款更不可靠多少」，是相对量。全部产品来源等级相同时，这个检验没有信息量，直接跳过。

### 判读

| 结果 | 含义 | 动作 |
|---|---|---|
| 第一名不变 | 推荐在数据误差范围内是稳的 | 可以放心 |
| 第一名翻转 | 原推荐建立在乐观数据上 | **去核数据**，不是改结论 |
| 名次变但第一名不变 | 中间名次的可靠性差 | 只影响「第二备选」怎么选 |

### 失效边界

- 它假设不利方向**一致**（全往坏的方向偏）。如果某项可能往好方向偏（厂商标低了），这个检验偏保守。
- σ 是人为赋予的，不是测出来的。它的作用是把「数据质量差异」显性化，不是精确估计误差。
- 只有 2 个候选时，翻转的概率极高（归一化本身就是 0/1 极端），这时它的参考价值下降。

### 与书里 risk profile 的区别

risk profile 要估概率、画合意曲线、算期望效用。这里只取区间端点，不算期望。原因：消费场景的概率估不准，但「哪些数据不可靠」判断得很准——问能答准的问题。

## 五、Pareto 前沿

### 定义

属性集上，A **支配** B 当且仅当：

- A 在综合得分上 ≥ B，**且**
- A 在横轴指标上不劣于 B（价格轴上：A 价格 ≤ B 价格；物理轴上按方向判断），**且**
- 至少一项严格优于

不被任何其他候选支配的点，构成**非支配解集**（Pareto 前沿）。

### 两条轴

| 图 | 横轴 | 回答 |
|---|---|---|
| 主图 | 价格 | 该花多少钱？多花 500 块买到了什么？ |
| 副图 | 品类核心物理轴 | 多减 100g 划不划算？ |

主图上的每一款都是「在这个价位没有更好的」。前沿的**斜率**才是关键信息：

```
¥1,299 → 得分 71
¥1,899 → 得分 78   ← 多花 600 买 7 分（86 元/分）
¥2,499 → 得分 82   ← 多花 600 买 4 分（150 元/分）
```

斜率变陡的地方，就是边际效用开始下降的地方。**通常推荐在拐点处或拐点前一档。**

### 失效边界

- **候选 < 4 个时前沿几乎无意义**：大部分点都是非支配的。此时改用「直接对比 + 分档」。
- 前沿只处理两个维度。三个以上维度的取舍，前沿表达不了——那些维度已经折进综合得分里了，所以你得接受「得分已经替你做了加权求和」这个前提。
- 前沿不告诉你「哪个更好」，只告诉你「哪些不值得考虑」。

## 六、价格分档

按给定边界切段，每段内选得分最高。区间采用 `[下界, 上界)`，最后一档为 `[最后边界, +∞)`；价格等于边界时只进入一个档位，边界不能重复。

```
< ¥1,000     → C 款（得分 65）
¥1,000–2,000 → B 款（得分 78）
¥2,000–3,000 → A 款（得分 82）
```

分档的作用不是推荐，是**展示每一档的天花板**。用户看到「多加 600 能从 65 跳到 78，再加 500 只到 82」之后，钱该怎么花自己就清楚了。

**边界要贴合市场实际**，不要用 1000/2000/3000 这种整数硬切。先看候选的价格分布，在自然断层处切。

## 七、什么时候不该用矩阵

诚实度要求：以下情况要说「矩阵帮不上」，而不是硬跑一份。

| 情况 | 为什么 | 替代 |
|---|---|---|
| 候选只有 2 个 | 归一化后一个 1 一个 0，加权求和退化为「谁在你最看重的维度上赢」 | 直接列差异，让用户选 |
| 关键属性缺失超过 30% | 归一化建立在残缺数据上 | 先补数据，或明说「数据不足，结论仅作参考」 |
| 属性高度相关（相关 > 0.8） | 权重被双计 | 合并属性 |
| 用户真正的决定因素不在表里 | 比如「我只想要那个牌子」 | 直接承认，别用矩阵包装 |
| 安全类产品门槛未过 | 不给权衡空间 | 直接出局 |

## 八、脚本调用

```bash
# 完整流程：归一化 + 打分 + 排名 + 权重敏感性 + 数据误差 + 双前沿 + 分档
python3 scripts/pick.py run \
  --attrs "蓬松度:+,总重:-,压缩体积:-,面料:+,充绒量:+" \
  --weights "45.7,25.7,15.7,9.0,4.0" \
  --data "A款:800,780,8.2,4,450;B款:850,1050,9.5,3,500;C款:750,620,6.8,2,380" \
  --price "A款:2499,B款:1899,C款:1299" \
  --axis 总重 \
  --bands "1000,2000" \
  --gates "A款:pass;B款:pass;C款:fail" \
  --worst "A款:0,B款:0.05,C款:0.12"

# 预算重算
python3 scripts/pick.py run ... --max-price 2000

# 只要权重换算
python3 scripts/pick.py roc --order "总重,蓬松度,压缩体积,面料,充绒量"
```

`--json` 拿结构化输出（供二次处理或存盘），可以放在脚本名后或子命令后。
