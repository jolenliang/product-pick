# 属性设计 · Attribute Design

Step 2 的细则。属性选错，后面所有计算都是精确的错误。

---

## 一、三层怎么分

判定顺序：**先问"不满足会不会直接不能用"，再问"能不能用数字比"，最后剩下的才是主观项。**

### 硬门槛（0–3 条）

判定句：**"如果这一项不达标，其他项再好我也不会买"** —— 成立就是门槛。

特征：
- 二元结果（合格/不合格），不是连续值
- 不参与加权，一票否决
- 通常来自尺寸、兼容、安全、法规

例：
- 睡袋：舒适温标 ≥ 使用环境最低温 + 5℃（怕冷者）、身长 ≥ 身高 + 10cm、与现有睡垫 R 值匹配
- 跑鞋：楦型适配（宽楦脚不能买窄楦）、无致伤风险的结构缺陷
- 相机：卡口兼容、法兰距兼容
- 户外硬装备：认证齐全（无认证直接出局）

**门槛要少。** 超过 3 条通常说明把偏好伪装成了门槛——「必须是黑色」不是门槛，是主观项；「必须能塞进 38L 背包」是门槛。

### 可量化项（5–8 个）

判定句：**"这一项有单位、能查到一个数、两个产品之间能比较大小"** —— 成立就是可量化。

必须写明四件事：

| 字段 | 例 |
|---|---|
| 名称 | 蓬松度 |
| 单位 | FP（fill power） |
| 方向 | 越大越好 `+` |
| 依据 | 这是评价羽绒保暖效率的核心指标，专业横评普遍以 700/800/900 分档 |

### 主观项（0–2 个）

判定句：**"这一项只能靠个人感受，但确实会影响我用不用它"** —— 成立就是主观项。

例：版型合身度、颜值、收纳顺手、按键手感、握持感。

主观项**不参与加权**，只在结论阶段行使否决权：如果第一名在这项上不合你意，建议作废，换第二名。理由：加权会把「不合身」稀释成「扣 8 分」，而现实中不合身是致命的。

## 二、数量控制（重要）

可量化项不是越多越好，有两个硬约束：

### 约束一：ROC 权重会被稀释

用户只给排序，权重由 ROC 换算。属性越多，分布越平坦：

| 属性数 n | 第一名权重 | 最后一名的权重 |
|---|---|---|
| 4 | 52.1% | 6.3% |
| 5 | 45.7% | 4.0% |
| 6 | 40.8% | 2.8% |
| 7 | 37.0% | 2.0% |
| 8 | 34.0% | 1.5% |

**含义**：属性从 5 个加到 8 个，你最看重的那个维度的话语权从 46% 掉到 34%，排名会更接近等权——**你以为加的是信息，其实加的是噪音**。

所以默认 5 个，最多 8 个。要加就加有区分度的，不要「多一个总比少一个好」。

### 约束二：属性间不能高度重叠

两个属性如果测的是同一件事，等于给它双倍权重。

| 重叠对 | 问题 | 处理 |
|---|---|---|
| 蓬松度 + 保暖重量比 | 后者基本由前者和充绒量决定 | 二选一，留蓬松度 |
| 总重 + 压缩体积 | 羽绒品类里高度相关，但不等同（面料厚度影响） | 都留，但要在表里注明相关性 |
| 屏幕分辨率 + 屏幕素质 | 后者包含前者 | 只留「屏幕素质」，用评分而非分辨率 |
| 品牌 + 售后 | 高度相关但不完全 | 留售后，品牌删掉（品牌不产生效用） |

判据：**如果 A 高的产品 B 几乎必然也高，那就只留一个。**

---

## 三、属性命名纪律

- **用可查证的名词，不用形容词**：「总重（g）」可以，「轻量化程度」不行
- **带单位**：`总重(g)` 不是 `总重`
- **方向明确**：`+` 越大越好，`-` 越小越好
- **不用总分型属性**：「综合评分」这种从别处抄来的总分，你不知道它怎么算的，不能进表

## 四、六品类属性范例

以下是**起点，不是模板**。每个品类必须重新搜索确认，因为市场在变。

### 睡袋

| 层 | 属性 | 说明 |
|---|---|---|
| 门槛 | EN/ISO 23537 舒适温标 ≤ 环境最低温 | 只认 T-Comfort，不认「极限温标」 |
| 门槛 | 身长适配 | 通常身高 + 10–15cm |
| 门槛 | 拉链侧（若需拼合） | 左/右要匹配 |
| 量化 | 总重（g）`-` | 含收纳袋？要确认口径 |
| 量化 | 蓬松度（FP）`+` | 700 起步，800 优秀，900+ 溢价大 |
| 量化 | 压缩体积（L）`-` | 决定背包占用 |
| 量化 | 面料防泼水/透气 `+` | DWR 等级或静水压 |
| 量化 | 充绒量（g）`+` | 与蓬松度共同决定保暖 |
| 量化 | 结构（盒式/缝穿）`+` | 盒式无冷点，但更重更贵 |
| 主观 | 版型合身、面料手感 | 否决项 |

> 注意：蓬松度与充绒量都留，但要在表里注明「两者共同决定保暖，同时高者形成优势叠加」，避免用户误以为这是两个独立收益。

### 跑鞋

| 层 | 属性 | 说明 |
|---|---|---|
| 门槛 | 楦型适配 | 宽楦/窄楦，不合脚直接出局 |
| 门槛 | 无已知致伤结构问题 | 如过度灵活的后跟 |
| 量化 | 重量（g，单只 42 码）`-` | 官标常不含鞋垫 |
| 量化 | 中底缓震（实测硬度/回弹）`+` | 只看实测，不看宣传材料名 |
| 量化 | 落差（mm）`?` | 视跑法而定，非单调，要用户指定偏好方向 |
| 量化 | 大底耐磨（实测里程）`+` | 长测数据 |
| 量化 | 透气性 `+` | 实测或主观评分 |
| 主观 | 包裹感、鞋面舒适 | 否决项 |

## 五、常见错误

| 错误 | 现象 | 修正 |
|---|---|---|
| **伪属性** | 「品牌知名度」「性价比」进表 | 品牌不产生效用，性价比是结论不是属性 |
| **总分属性** | 抄来一个「综合评分 8.5/10」 | 不知道算法，不能进表 |
| **重叠属性** | 蓬松度 + 保暖重量比 | 只留一个 |
| **不可查属性** | 「做工精良」 | 改成可查的（缝线密度、保修年限）或降为主观项 |
| **把偏好当门槛** | 「必须黑色」 | 进主观项 |
| **把门槛当偏好** | 「尽量买安全认证全的吧」 | 安全类是门槛，不是「尽量」 |
| **属性数超标** | 12 个可量化项 | ROC 权重被稀释到无意义，砍到 8 以内 |
| **方向写反** | 重量标 `+` | 归一化会把最重的算成最好，结论全反 |

## 六、交付给用户的形式

```
这个品类的核心属性（已搜过 8 类渠道确认）：

【硬门槛】不合格直接出局，不参与打分
1. EN/ISO 23537 舒适温标 ≤ 环境最低温 − 5℃
2. 身长 ≥ 178cm（你 181cm，需加长版）

【可量化】5 个，等会儿要你排优先级
1. 总重（g）· 越小越好 · 依据：长距离徒步的重量惩罚是累积的
2. 蓬松度（FP）· 越大越好 · 依据：横评常用分档
...

【主观】不参与打分，只在最后行使否决权
1. 版型合身度

这 5 个够吗？要加、删、换哪个？
```
